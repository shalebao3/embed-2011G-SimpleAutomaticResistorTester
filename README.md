# 2011G 简易自动电阻测试仪

基于 **STM32F103C8T6 + STM32F10x 标准外设库** 实现 2011G 简易自动电阻测试仪。

当前项目从通用 STM32F103C8T6 标准库模板创建，现阶段处于：

> **题目需求拆解 + 测量原理分析 + 硬件/软件方案设计阶段**

目前先聚焦基本测量功能，发挥部分暂不展开。

## 2. 当前对测量原理的理解

STM32 的 ADC **不能直接测量电阻**。

真正的测量链路是：

```text
已知参考电阻 Rref
        │
        ├──── 与待测电阻 Rx 构成测量电路
        │
        ▼
产生一个与 Rx 有关的模拟电压
        │
        ▼
STM32 ADC 引脚
        │
        ▼
ADC 得到数字量
        │
        ▼
CPU 根据电压、Rref 和电路关系
反推出待测电阻 Rx
```

因此：

- **ADC 测的是电压**
- **软件算出来的才是电阻值**
- 参考电阻是整个测量电路的重要基准

当前优先考虑使用简单、容易分析的 **电阻分压法** 作为基本测量模型。

具体电路拓扑、参考电阻阻值和精度等级仍需结合题目要求继续确定。

## 3. 为什么需要分量程

如果整个测量范围只使用一个固定参考电阻，会出现严重的动态范围问题。

例如：

- 参考电阻太小，测很大的待测电阻时，ADC 电压可能长期挤在接近满量程的位置
- 参考电阻太大，测很小的待测电阻时，ADC 电压可能长期挤在接近 0 的位置

这两种情况都会导致：

- ADC 有效分辨率下降
- 少量 ADC 误差被放大
- 电阻计算误差增大

所以自动电阻测试仪需要根据被测电阻的大致范围，切换不同的参考电阻，让 ADC 电压尽量工作在一个较合适的区间。

可以类比为：

> 用不同量程的尺子测不同大小的物体，而不是拿同一把尺子同时测头发和房子。

## 4. 自动量程的基本架构

当前讨论确定的核心架构是：

```text
             ┌──── 参考电阻 R1 ────┐
             ├──── 参考电阻 R2 ────┤
GPIO ───────→│    模拟开关/继电器    │
             ├──── 参考电阻 R3 ────┤
             └──── 高阻测量支路 ? ──┘
                        │
                        ▼
                  待测电阻 Rx
                        │
                        ▼
                    测量节点
                        │
                        ▼
                       ADC
                        │
                        ▼
                      CPU
                        │
             判断当前量程是否合适
                        │
                        └────→ GPIO 切换量程
```

这里有一个非常重要的区分：

### ADC：负责“感知”

ADC 把测量节点的模拟电压转换成数字值。

### CPU：负责“判断”

程序读取 ADC 值，根据设定的阈值判断：

- 当前量程是否合适
- 是否需要换更大或更小的参考电阻
- 当前应该使用哪个参考电阻进行最终计算

### GPIO：负责“执行”

GPIO 本身不会读取 ADC 的反馈，也不会计算电阻。

GPIO 只是由 CPU 控制输出高低电平，用于驱动：

- 模拟开关
- 多路复用器
- 继电器
- 其他量程切换电路

也就是说：

```text
ADC = 眼睛
CPU = 大脑
GPIO = 手
```

---

## 5. GPIO 与 ADC 不是串联关系

需要避免下面这种错误理解：

```text
待测电阻 → GPIO → ADC
```

实际情况更接近：

```text
待测电阻 + 参考电阻
        │
        ▼
     模拟电压
        │
        ▼
ADC 模拟输入引脚
```

而 GPIO 输出位于另一条控制链：

```text
CPU
 │
 ▼
GPIO 输出
 │
 ▼
模拟开关 / 继电器
 │
 ▼
选择当前参考电阻
```

STM32 的某些物理引脚既具有普通 GPIO 功能，也具有 ADC 复用功能。

当一个引脚配置为 ADC 模拟输入后，应把它理解成：

> **这个物理引脚现在服务于 ADC，而不是模拟信号先经过普通 GPIO 再进入 ADC。**

---

## 6. 自动换挡不是等 ADC “溢出”

自动量程不应该等 ADC 真正到达 0 或满量程后才处理。

更合理的做法是设置：

- ADC 下阈值
- ADC 上阈值

例如抽象为：

```text
ADC 太低
    ↓
当前参考电阻/量程不合适
    ↓
切换量程

ADC 落在有效区间
    ↓
保持当前量程
    ↓
计算最终电阻

ADC 太高
    ↓
当前参考电阻/量程不合适
    ↓
切换量程
```

最终阈值不能现在拍脑袋确定，需要在电路、ADC 参考电压、参考电阻和目标精度确定之后再计算。

### 推荐的软件流程

```text
选择初始量程
    ↓
等待模拟电路稳定
    ↓
ADC 采样
    ↓
判断 ADC 是否进入有效区间
    │
    ├── 否 → GPIO 切换量程 → 重新采样
    │
    └── 是
         ↓
根据当前 Rref 计算 Rx
         ↓
滤波 / 修正
         ↓
显示结果
```

## 7. 当前涉及的 STM32 外设

### 7.1 ADC —— 核心外设

ADC 是本题最核心的新外设。

主要职责：

- 采集电阻测量电路产生的模拟电压
- 为自动量程判断提供输入
- 为最终电阻计算提供原始数据

当前阶段优先使用：

> **软件触发 ADC**

原因是电阻测量的刷新频率很低，没有必要一开始就引入复杂的定时器硬件触发。

---

### 7.2 GPIO 输出 —— 自动量程

GPIO 输出主要负责：

- 选择参考电阻
- 控制模拟开关或继电器
- 完成自动换挡

GPIO **不直接负责测量电阻**。

---

### 7.3 GPIO 输入 / EXTI —— 可选

如果后续题目需要按键，例如：

- 功能切换
- 参数设置
- 筛选模式
- 手动操作

可以使用普通 GPIO 输入。

如果需要按键中断，再考虑 EXTI。

这部分目前不是电阻测量主线。

---

### 7.4 TIM —— 当前不是必需外设

本题基本测量功能 **不要求为了 ADC 而强行使用定时器**。

TIM 后续可能用于：

- 周期测量
- 固定刷新节奏
- ADC 硬件触发
- 动态扫描数码管

但这些都属于实现方式或后续优化。

当前阶段：

> **优先采用软件触发 ADC，不为了使用 TIM 而使用 TIM。**

---

### 7.5 显示接口 —— 待确定

最终需要将测得的电阻值显示出来。

显示方案暂未确定，可根据后续硬件选择：

- 数码管
- LCD
- OLED
- 其他显示模块

如果采用动态扫描数码管，可能额外使用 TIM。

## 8. 软件与硬件必须同步设计

这道题不能只写 STM32 软件。

原因是软件中的这些参数：

- ADC 计算公式
- 自动换挡阈值
- 参考电阻值
- 量程边界
- 稳定等待时间
- 滤波策略
- 校准系数

全部依赖实际模拟测量电路。

因此后续应同步推进：

```text
测量电路设计
      ↕
参考电阻选择
      ↕
量程切换电路
      ↕
ADC 配置
      ↕
自动量程算法
      ↕
电阻计算
```

不能先完全脱离硬件写完软件，再回头考虑电路。

```text

    │
    ▼

    │
    ▼

    │

```

```text

    │
    ▼

    │
```

### 尚未确定

以下内容目前不能视为最终方案：

- 参考电阻具体阻值
- 参考电阻精度
- 使用模拟开关还是继电器
- 测量节点具体连接方式
- ADC 参考电压方案
- 是否需要运算放大器
- 高阻档的具体电路
- 输入保护
- RC 滤波
- PCB 漏电对高阻测量的影响
- 校准方式

尤其是高阻测量，与普通低阻/中阻量程相比，对：

- 漏电流
- 板面清洁
- 模拟开关漏电
- ADC 输入阻抗
- PCB 布局

会更加敏感，需要单独分析。

## 14. 本地环境

首次克隆时需要同时拉取标准库 submodule：

```bash
git clone --recurse-submodules https://github.com/shalebao3/embed-2011G-SimpleAutomaticResistorTester.git
```

如果已经 clone，但标准库目录为空：

```bash
git submodule update --init --recursive
```

macOS 开发环境需要能够执行：

```bash
arm-none-eabi-gcc --version
cmake --version
ninja --version
```

构建：

```bash
cmake --preset Debug -S firmware
cmake --build --preset Debug
```

构建产物名称跟随当前 CMake 工程名：

```text
embed-2011G-SimpleAutomaticResistorTester.elf
embed-2011G-SimpleAutomaticResistorTester.hex
embed-2011G-SimpleAutomaticResistorTester.bin
embed-2011G-SimpleAutomaticResistorTester.map
```
